# 数据采集与处理

## 采集

SO-101 主从臂遥操作，外部与腕部 RGB 相机 640×480、30 FPS，机器人采集循环25 Hz。正式示范140条、55,999帧；每条目标16秒，重置8秒，任务始终为先红后蓝入盒。

## 转换与检查

原始 LeRobot v3.0 数据保留，独立导出 v2.1 兼容副本。按 episode 拆分 parquet 和视频，保留状态、动作、任务文本及时间戳语义。检查结构、数值有限性、视频帧数、PTS、重复帧及转换前后内容对应；不自动平移状态或动作。

## 划分

以完整 episode 为单位，随机种子42，结合采集批次配额及实际颜色布局分层划分，源 episode 互不重叠：训练100条39,999帧，验证20条8,000帧，测试20条8,000帧。实际索引与方法见 configs/split.json；重建原划分应使用冻结索引。

实际140条的左右布局为60/80，训练为43/57，验证9/11，测试8/12（前者为红左蓝右）。采集计划与实际布局不同，不将计划中的均衡当作实际统计。

## OpenPI 适配

front → base_0_rgb，wrist → left_wrist_0_rgb；第三路黑图占位、mask=False。RGB图像等比例缩放补边至224×224。状态与动作为6维：五个关节degree加LeRobot夹爪0–100，动作为绝对目标位置。状态及动作补齐至32维，动作窗口50步；episode末尾重复最后动作，不跨episode。

只用训练集计算状态、动作q01/q99分位数统计，保存于 configs/norm_stats.json，训练、验证、测试和推理共用。归一化在加载时执行，原始数据不覆盖。

已用实际OpenPI加载器验证三个集合的图像、掩码、状态、动作、token形状和episode边界。离线测试报告见 results/test_flow_loss.json；真机结果见 results/real_robot_test.json。

## 运行目录与外部资源

scripts 是按用途整理的源码。README中的准备命令将其恢复为原实验运行布局。数据集、预训练参数、最佳checkpoint、固定版本OpenPI/LeRobot源码及Python环境需单独准备，不包含在Git中。requirements.txt仅为CPU数据处理依赖，并继承已安装的机器人环境；云端需单独安装匹配GPU的JAX环境。

迁移时核对本地Python、串口、相机编号、机器人校准路径及ID、云端目录。配置JSON为参数记录，脚本当前通过training_config.py构建训练参数；修改JSON本身不会自动改变训练行为。发布版RTC经过模块合并并移除可选截图，原实验冻结版本仍保留本地，不能将发布代码视为原评测源码的逐字节副本。
